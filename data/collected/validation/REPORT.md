区分は**保存せず、表示時に latestMonth から計算**する（毎月書き換えが不要＝書き込みゼロ）。

### 現在の画面への影響（このまま投入した場合）

- 検索（`searchProducts`）: 全商品を「在庫あり店舗数 → 直近報告数」で並べるため、実データ投入直後は全件 0 で並びが不定になり、**2000 年代の商品が上位に混ざる**。→ 既定で current + upcoming に絞り、過去の商品は「過去の商品も含める」で表示。同点時は latestMonth の新しい順。
- 新着（`getNewProducts`）: releaseMonth の降順のため **2027 年発売予定の商品が「新着」に並ぶ**。→ 新着は latestMonth ≤ 今月、発売予定は別枠に。
- 商品数 23,464 件を毎回全件読み込む作り（下記 5・7）は、性能と無料枠の両面で成立しない。

## 5. 既存データへの影響

- 本番 Firestore には現在、**架空のモックデータ**（商品 10〔ねこだんご等〕・場所 8〔「デモ住所」〕・placements 34・stockReports 27・users 3）が入っている。
- 新しい ID（`bandai-…` `gp-…` 等）は既存の `p-001` `l-001` 形式と**衝突しない**（確認済み）。products / locations に書き込むだけなら、既存の placements・stockReports・users は変更されない。
- ただし投入後は実在の商品・店舗と架空の商品・店舗が**同じ画面に混在**する。公開前に、モックの products/locations と、それに紐づく placements/stockReports をまとめて削除するか、`isSample: true` を付けて表示から除外する必要がある（削除は利用者の判断で。今回は何もしていない）。
- モックの在庫報告（stockReports）はモック商品にのみ紐づき、実データの商品とは関係しない。

公式の識別子から作り、再収集・再投入しても同じ ID になるようにする（衝突 0 件をドライランで確認）。
すべて `^[A-Za-z0-9_-]{1,128}$`（在庫報告 API の ID 検証）を満たす。

|---|---|---:|

### 重複処理

- 商品: JAN・メーカー商品コード単位で 1 ドキュメント。同名の再販（別 ID）は別ドキュメントのまま、`productGroupKey`（メーカー＋正規化した商品名）を付けて画面でまとめる。
- 店舗: 「同名・同じ市区町村」38 組を統合してから投入。要確認の組は保留（投入しない）。
- 再実行時の重複: ID が決定的なので `set()` は同じドキュメントの上書き（増えない）。無駄な書き込みを避けるため、**成功した ID をローカルのチェックポイントファイルに記録し、再実行時はスキップ**（Firestore を読んで存在確認しない＝読み取りゼロ）。

### バッチサイズ・再試行・所要時間

- `WriteBatch` 400 件ずつ（上限 500）を順番にコミット。バッチ間 1 秒。
- 失敗時: `UNAVAILABLE` / `DEADLINE_EXCEEDED` / `ABORTED` は指数バックオフ（2・4・8・16・32 秒、最大 5 回）で同じバッチを再送。`RESOURCE_EXHAUSTED`（無料枠超過）・`PERMISSION_DENIED` は即停止し、チェックポイントから翌日再開。
- **書き込み件数が無料枠を超えるため 2 日に分割**（投入対象 24,909 件 > 20,000 件/日。在庫報告などのため 1 日 15,000 件までに抑える）:

| 日 | 店舗 | 商品 | 範囲 | バッチ数 | 目安時間 |
|---|---:|---:|---|---:|---|
| 1 日目 | 1,576 | 13,424 | 発売予定・現在 → 2021-05 | 38 | 約 1〜2 分 |
| 2 日目 | 0 | 9,909 | 2021-05 → 2000-02 | 25 | 約 1 分 |

- 投入前に必ず Firestore エミュレータで同じスクリプトを実行し、件数・ドキュメント内容を確認する。
- ドキュメントサイズ: 商品 平均 1.2KB・最大 6KB、店舗 平均 1.1KB（上限 1MB に対して十分小さい）。保存容量は約 29MB（無料枠 1GiB）。

### 既存データとの扱い

- `products` / `locations` には新 ID で追加するだけで、既存ドキュメントは上書きしない（ID 空間が別）。
- モックデータの削除・非表示は別作業（利用者の承認後）。
- 投入前に `gcloud firestore export` 相当のバックアップを推奨（Spark では不可のため、少なくとも既存 80 件程度をスクリプトで JSON に書き出す）。
